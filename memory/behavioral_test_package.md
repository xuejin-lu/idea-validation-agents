## Exact offer

提供給「使用官網加上多個電商通路的台灣公司」一份一個月的資料整理與差異準備包：

1. 收集買方提供的指定月份平台、金流、銀行、發票、退款/折讓檔案。
2. 將檔案整理成一份工作表，保留每筆資料的來源欄位。
3. 依雙方事先確認的欄位，核對可觀察的訂單、金額、入帳、發票、退款/折讓差異。
4. 產出差異與待確認清單，標明來源、狀態、責任人與下一步。
5. 產出交給買方記帳士/會計師的 handoff checklist。

這不是自動化軟體、稅務服務或正式記帳服務。

## Exact target segment

只使用已被證據支持的描述：

> 使用官網加上多個電商通路的台灣公司。

不自行假設公司規模、產業、營收、訂單量或平台組合。這些資訊由 intake form 收集，不能在行銷文案中寫成已驗證的 ICP。

## Fixed scope

- 一家公司、指定一個月份。
- 預先確認的平台/來源數量；初測建議最多 3 個銷售或金流來源，加上 1 個銀行/會計交接來源。
- 一次資料收件、一次缺件追問、一次結果說明。
- 交付：normalized working table、exception list、source/evidence index、accountant-handoff checklist。
- 不含平台串接、API、爬蟲、長期客服、訂單代處理或 ERP 導入。
- 不含未事先確認的資料清洗規則、歷史月份回溯或大量人工補登。
- 超出範圍時先停止並重新報價；不默默擴張。

## Explicit exclusions and professional boundary

不提供、也不宣稱提供：

- 稅務申報、稅務建議或稅務規劃；
- 正式記帳、傳票入帳、會計師/記帳士簽證或簽章；
- 會計報表認證、法律意見或法規合規保證；
- 代替買方與稅捐機關溝通；
- 任何「一定不會漏開發票」「保證合規」或「保證找回金額」的承諾。

台灣財政部規範涉及記帳及報稅代理業務的登錄、委任範圍與商業會計事務。若實際需求涉及正式記帳、申報或稅務判斷，必須轉由買方既有的合格專業人員審閱；在邊界未經專業人士確認前，不交付會被當作正式帳務或申報依據的結論。

## Required buyer inputs

- 公司/品牌名稱可用代號；不要求先提供統編。
- 指定月份與時區/結帳截止日。
- 使用中的平台與來源清單。
- 各平台、金流、銀行、電子發票或 ERP 匯出檔；初測接受 CSV/XLSX/PDF，是否可讀取由 intake 判斷。
- 買方目前採用的欄位定義或既有對帳表（若有）。
- 買方記帳士/會計師需要的交接格式（若已知）。
- 兩個以上的主要差異範例或買方認為最痛的例外。

## Expected output

- 一份帶有 source_file/source_row/source_period 欄位的 normalized working table。
- 一份 exception list：差異類型、金額/筆數區間、來源、狀態、待買方確認事項。
- 一份 source/evidence index：每個欄位可回到哪個原始檔或原始列。
- 一份 accountant-handoff checklist：哪些已整理、哪些尚待專業人士判斷。
- 一頁 limitations：本包未完成的事項與不得直接作為正式申報/簽證依據的提醒。

## Turnaround assumption

- 收到完整且已去識別化的檔案後，預估 3 個工作日內提供第一版。
- 這是測試用工作假設，不是 SLA 或保證；檔案缺漏、格式不一致或超出範圍時暫停計時。

## What counts as commitment

由弱至強：

1. 只詢問價格：不算承諾。
2. 願意填 intake：仍不算承諾。
3. 願意提供去識別化月份樣本並確認固定範圍：`commitment` 候選。
4. 接受書面固定範圍報價、排定開始日並承諾提供真實檔案：`commitment`。
5. 支付訂金/接受付費訂單：`paid_transaction`；在未發生前不可宣稱已有付款。

## Success signal

初期最強訊號不是瀏覽、按讚、提案數或「聽起來不錯」，而是：

- 至少 1 家符合 segment 的公司提供去識別化月份樣本；
- 接受同一份 fixed-scope quote 並排定開始日；
- 第二家公司的資料可用同一套輸入/輸出欄位描述。

進入 month-two testing 前，還需看到第一家買方交付後排定下一個月份，且主要例外仍可用同一套 taxonomy 管理。

## Kill criterion

- 沒有買方願意提供去識別化樣本或接受固定範圍。
- 每家買方都要求正式記帳、申報或稅務判斷，無合格夥伴可審閱。
- 兩家買方的輸入/輸出完全無法共用，或人工時數隨資料量 1:1 增長。
- 買方只要求免費諮詢、免費完整月結或模糊的「順便幫忙」。
- 任一方要求提供帳號密碼、OTP、未遮蔽個資或直接操作銀行/發票後台。

## Maximum validation spend

- 上限：NT$5,000。
- 目標：NT$0–1,500；先用既有 marketplace/community/partner channel，不投廣告、不買名單、不建軟體。
- 可能支出：安全檔案處理/儲存、必要的合格會計專業諮詢或少量平台費用；每筆支出先記錄用途。

## What justifies month-two testing

同一買方在第一版交付後，明確排定下一個月份並願意再次提供檔案；第一個月的例外類型可被保留為下一月 checklist；且專業會計審閱者確認輸出仍是資料準備/交接材料，而非未授權的正式帳務或稅務服務。
